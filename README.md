Версия 1.10: перед использованием прочитайте **UPDATE_1_10.md** (предыдущие изменения — в UPDATE_1_9.md, UPDATE_1_8.md и UPDATE_1_7.md).
Это отладочная версия, не клинически валидированный продукт.
Сырые значения OCR могут быть ошибочны; требуется сверка с оригиналом.
Проверка синтетических сценариев: `python -m unittest discover -s tests -v`.

Локальная система по ТЗ «ПреОпКонтроль» (одна клиника, без регистрации продукта).
Переработка вашего кода: сохранена общая идея (загрузка → OCR → анализ → отчет),
но конвейер построен по модулям ТЗ.

## Что изменилось по сравнению с вашей версией

| Было | Стало |

## Установка (Windows, компьютер клиники)

1. Python 3.12+ (python.org, галочка «Add to PATH»).
2. Tesseract с русским языком:
   - установщик: github.com/UB-Mannheim/tesseract/wiki
   - в установщике выбрать русский язык (rus);
   - если путь нестандартный — задать переменную окружения
     `TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe`.
3. Установить зависимости:
   ```
   pip install -r requirements.txt
   ```
4. Запуск:
   ```
   python preop_check\server.py
   ```
5. Открыть в браузере: http://127.0.0.1:8080

Проверка без браузера (на ваших тестовых файлах):
```
python test_run.py
```

## Как работает

```
Загрузка (PDF/JPG/PNG) → сохранение оригинала в storage/ (контур)
→ текстовый слой PDF или OCR (Tesseract, rus+eng, уверенность по словам)
→ классификация документа (ОАК, биохимия, коагулограмма, осмотры…)
→ карточка пациента (возраст считается на дату операции)
→ автоконтроль распознавания
→ обезличивание
→ правила приказа №41-ОД: базовые + направление + возраст + патологии
→ комплектность, сроки, референсы
→ отчет: карточка + таблица + сводка
```

## Что вошло в MVP, что нет

Вошло (М1–М13 ТЗ в объеме MVP):
- текстовый слой PDF + OCR с проверкой уверенности;
- классификация 20 типов документов;
- извлечение 26 лабораторных показателей с единицами и референсами бланка;
- невозможные значения (калий 42 ммоль/л и т.п.) блокируются, а не исправляются «по смыслу»;
- приказ №41-ОД в виде правил: 11 базовых, направления, возраст >60, 9 групп патологий (каждая строка отдельно);
- срок годности каждого обследования к дате операции;
- сводка: не найдено / частично / просрочено / отклонения / вне плана / не распознано / противоречия;
- обезличивание перед анализом, оригиналы только в storage/;
- локальный сервер 127.0.0.1, без внешних вызовов и CDN.

Не вошло (следующие шаги по ТЗ):
- второй-третий «читатель» для тройной проверки (PaddleOCR, Qwen2.5-VL) — точки
  расширения в validator.py; для рукописных документов обязательна GPU-машина;
- база данных (PostgreSQL) вместо папки storage/ — сейчас состояние случая не сохраняется;
- журнал аудита в БД, роли и авторизация (сейчас доступ без входа — только до пилота);
- справочник референсов лаборатории (сейчас: бланк → запасной справочник в rules.py);
- возраст >60, направление и патологии сейчас берутся из формы на сайте
  (частично извлекаются из документов).

## Настройка правил

Все правила приказа — в `preop_check/rules.py` (структура Rule). Сроки годности,
состав групп, патологии правятся без изменения логики. Любое изменение — только
после утверждения врачом и с новой версией (`PROTOCOL_VERSION`).

## Ограничения

- Сканы без текстового слоя требуют установленного русского Tesseract
  (проверено: скан ЭКГ без rus-пакета дает мусор — система помечает низкую
  уверенность и не использует такой текст);
- рукописные документы в MVP не распознаются (нужен Qwen2.5-VL, этап 3 ТЗ);
- даты обследования извлекаются по меткам («Дата забора», «Дата осмотра»,
  «Время исследования») и по самой частой дате вне строк лицензий — для
  нестандартных бланков может потребоваться донастройка;
- EKG.PDF из тестового набора — скан: на машине без tesseract-rus он не
  классифицируется, после установки rus будет распознан;
- продукт внутренний: продажа и передача другим организациям — только после
  оценки статуса медицинского изделия (см. ТЗ, п. 13).

## Соответствие 152-ФЗ в MVP

- обработки вне контура нет (внешних вызовов нет);
- оригиналы в локальной папке storage/, в отчет ФИО не попадает;
- обезличивание базовое; локальные акты, модель угроз и согласия — за клиникой
  до промышленной эксплуатации (ТЗ, п. 8).
